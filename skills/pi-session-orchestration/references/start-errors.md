# Start errors of `pi_session_start`

Load this file only after a `pi_session_start` call has failed. Classify the error by its `code` alone. Never decide by the message, provider text or any other free text, and never infer a cause. Each code below is in exactly one class.

- Operator needed (do not retry and do not switch to another profile; report the code and stop that task): `unknown_execution_profile`, `unknown_workspace`, `workspace_mode_forbids_coding`, `unknown_provider`, `unknown_model`, `model_unavailable`, `max_output_tokens_unsupported`, `thinking_level_unavailable`, `local_authentication_missing`, `execution_selection_mismatch`, `skill_load_failed`, `sandbox_unavailable`, `extension_not_installed`, `extension_version_mismatch`, `extension_tool_conflict`, `extension_tool_missing`, `external_mcp_no_tools`, `external_mcp_grant_tool_missing`, `external_mcp_activation_mismatch`, `writer_not_ready`, `writer_fenced`, `container_runtime_unavailable`, `provider_unsupported_in_writer`, `snapshot_profile_unsupported`, `snapshot_unavailable`, `snapshot_modified`, `server_stopping`. Writer readiness needs repository setup and acceptance; a fenced writer needs the operator to confirm that its container is gone; runtime unavailability needs usable rootless Podman; an unsupported writer provider needs a non-loopback endpoint; a snapshot code needs the operator to pick a profile without extensions or external MCP servers, or to (re)materialize the snapshot slot with setup. The last code means the server is shutting down: a new server process is needed, not a retry.
- Controller action (do not blindly retry or switch profiles; collect and reset the writer for uncollected work, or wait for or close the open coding session for a busy writer; resolve pool state, lost sessions or inapplicable base before a fresh start): `writer_uncollected`, `writer_busy`, `writer_unavailable`, `writer_session_lost`, `base_not_applicable`.
- Routing (do not repeat the same request; correct it once, or start once with an explicit profile under the same workspace and family rules, otherwise report the code): `routing_off`, `routing_profile_conflict`, `routing_role_required`, `routing_tier_below_floor`, `routing_author_required`, `routing_same_family`, `routing_no_candidate`.
- Transient (retry at most once after a pause, then report): `external_mcp_unavailable` (an external MCP server that cannot connect, times out or breaks the protocol), `extension_load_failed` (an invalid package, but also a start timeout), `local_authentication_unavailable` (local authentication could not be resolved within its deadline).
- Unknown (report the code; at most one retry in a fresh session): `pi_session_creation_failed`. Any code not listed above is also unknown.

Pool unavailability is a capacity/state signal: reason `none_ready` means no ready writer with current acceptance, `none_at_base` means none of the ready writers matches the requested/default base, and `none_admitted` means candidates refused, with content-free counts `busy`, `notAtBaseline`, `settingsChanged`. Wait for capacity or collect/finish writers; readiness or settings drift may need operator reconciliation, never a profile switch. Setup on a held writer fails after a short lease wait.

Session loss also applies to further prompts after idle or running transport loss: get and close still work; close and inspect/collect work before a fresh session, not a blind repeat of a prompt. An inapplicable base means no session was created: omit `base` unless using a coding profile on a container workspace. For fix rounds create a local branch at the collected ref, reset with `--writer <name> --reset --base <branch> --apply`, then start with `base: "<branch>"` and collect the `writer` returned. No reconnect is needed.

A routing code means that routing chose no profile and no session was created. `routing_off`: routing is off; start with an explicit profile or the default, without `tier` and `role`. `routing_profile_conflict`: send `executionProfile` or `tier`, never both. `routing_role_required`: add the `role` the `tier` is for. `routing_tier_below_floor`: omit `tier` or raise it. `routing_author_required`: add the author's family from capabilities' `routing.families` or, for your own work, your model's configured family label; ask rather than invent one. `routing_no_candidate` and `routing_same_family`: no profile of the tier fits the role, workspace mode, `shell` and suspensions, or only the author's family fits. Start once with an explicit profile that the workspace mode admits and that, for a review, belongs to another family than the author's; use `allowSameFamily: true` only as a conscious override when no other family is available, and report the code when no such profile exists.
