## The next investment: decide isolation

[#79](https://github.com/plagor44-ux/pi-session-mcp/issues/79) authorizes a
decision, not an implementation. Sprint 4 decides that isolation is next, not
how. ADR 0008 (Proposed) must compare at least:

1. operator-environment containment with no server change (separate OS user,
   container or VM per writer, separate clone);
2. whole-process self-restriction of the server on Linux, and the macOS
   equivalent or gap;
3. moving Pi out of process per session, which would amend ADR 0002.

Two facts constrain the options. `edit` and `write` run inside the server
process and only `bash` runs as a child process, so confining `bash` alone
would give false assurance. One server process serves every session of a
client, so whole-process confinement can only allow the union of all
workspaces plus Pi's agent directory and the provider network. The ADR also
names the threats each option addresses: model error, prompt injection from
repository content or `AGENTS.md`, and trusted extension code. Filesystem
confinement does nothing against extension code or exfiltration through the
provider. Its acceptance is a synthetic isolated-write test that covers
`edit` and `write` as well as `bash`.

The strongest argument against expansion remains the security and
maintenance surface it adds to a deliberately small local server; option 1
keeps that surface unchanged.

## Interim operating rules

Maintainer decision on 2026-10-15: until ADR 0008 is accepted, coding
profiles keep running on non-disposable repositories under these rules. They
are operator practice; the server enforces none of them.

- Coding profiles only on dedicated worktrees of trusted repositories, one
  writer per alias; never on untrusted content.
- Skill catalog and override directories outside every workspace.
- Every worker diff is reviewed before it leaves the worktree.
- Cursor-backed profiles only where a write would be uncritical.

These rules limit the damage of mistakes. They do not contain a misbehaving
worker. Accepted residual risks, as the two reviews of this decision named
them:

- A Git worktree is not a boundary: it shares configuration, hooks, refs and
  objects with its main repository, so a change to `.git/hooks` or
  `.git/config` can run code in the operator's later Git commands.
- `bash` runs with the server's OS identity, network access and inherited
  credentials, so a worker can commit, push, or call `gh` and `ssh` before any
  diff review.
- Files outside the workspace stay reachable, among them the Pi Session MCP
  configuration file, client configurations, the installed controller skills,
  shell start-up files, user cron and service units, `~/.ssh` and any other
  credential readable by the OS identity; `read` is not path-confined in
  `read-only` profiles either.
- The Cursor runtime starts processes of its own (`git`, `ssh`, `gh`, its MCP
  servers), also in `read-only` profiles, and can write below `~/.pi/agent`,
  `~/.cursor/projects/` and `<workspace>/.pi/`.
- External MCP grants of the operator profiles were not covered by acceptance.
- No decision date is set for ADR 0008, so the interim period is open-ended.
