## Prepared development path and smallest next decision

A dedicated `--footprint-live` adapter now represents L1/L2/L3 beside the existing
profile runner. It preserves `validateApproval` and adds a separate exact-schedule
operator decision binding current sources, compiled build, controller skill,
manifest, budget and routes. The generic runner and its schemas remain intact.
The three execution templates are generated by `--footprint-plan`; all approval
flags remain false and the advisory amount remains null. They are proposals,
not authorized model use.

The existing gate requires a positive **operator-selected advisory** USD amount
and explicit acknowledgment of unmetered use. That amount is neither a measured
subscription cost nor a hard ceiling. No value was invented here. Once the
operator supplies the exact pilot decision and advisory amount, bind the approved
manifest/budget/decision digests and execute exactly three fresh sequential Codex
controllers, four worker starts and five work turns, without whole-run retries.
No historical approval is reusable.

L3 uses two independent read sessions sharing the same disposable immutable T1
fixture, then one follow-up in the first session. Re-fetching that original turn
for invariance is explicit verification overhead, separate from normal terminal
consumption. Each turn is keyed by actual session/turn identity transiently;
records export only ordinals and allowlisted metrics. Independent oracles and
scope snapshots remain separate from worker claims.

The first pilot has since passed (see `m1-pilot/README.md`). Only after it establishes usable
routes, client-event measurements and cleanup should a new, specifically approved
three-pair alternating A/B compare compact reports or terminal-consumption practice.
No live quality, token saving, model ranking or Level-3 claim follows from the
provider-free calibration. The local model-request fixture establishes only its
declared Codex/loopback route. No provider configuration, client registration,
credential store or installed skill was changed by this development work.

## Draft skill instruction for a later approved A/B

Request a concise report containing task status, actual changed paths, checks with
exit codes and failures, blockers, risks and relative evidence references. Include
source-linked findings needed to verify the task. Keep full diffs/logs out of the
default report and retrieve them when needed. Preserve failures even when the turn
completed. A size target is advisory: if required evidence will not fit, report the
limit explicitly instead of dropping it. The controller verifies files/tests and
consumes each terminal result once. This was a local draft on 2026-10-17; no skill
was installed or changed then. Sprint 5 later implemented it in the worker skills (#87).
